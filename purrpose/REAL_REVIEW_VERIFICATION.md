# Real-source review and H-MEM verification

24 October 2026. `real_review.py` connects the existing fixed Lucy reader to bounded code roles and the official H-MEM reference. It is not general model planning, a full arbitrary-document evaluator or a real-case qualification engine.

## Actual behavior

- A fresh requested read recalls the REAL-LUCY-GHS scoped review, if H-MEM is configured. Previous gaps become explicit coordinator context. Failed recall/save is review_incomplete, not pretend memory.
- Source fingerprints select changed sources. Candidates are always re-grounded against currently retrieved text; unchanged saved observations do not automatically become current verified evidence.
- Identity/risk and funding/channel roles inspect saved, dated manual observations when their inputs change; otherwise retain them as dated unresolved observations. Neither role fetches new registry/form data or clears a gate.
- Rescue-need code produces narrow candidate statements. If pregnancy and birth accounts are both found, the evaluator delegates chronological resolution. A dated later birth account plus complete configured-page read permits revising the reported account. Otherwise the issue stays unresolved without extra fetches. The coordinator/evaluator feedback causes a conditional branch, not six compulsory model calls.
- All six real gates remain unresolved; qualified=false and remaining_minor=null. The chronology result is an organization account, not independently confirmed clinical need. Risk holds in a prior compatible record are retained in the saved payload; no real qualification route exists here.
- Source IDs, URLs, dates, observed read time, candidate quotes, hashes, gaps, saved manual observation copies and pending summary are stored. Full fetched HTML/body is not stored in H-MEM.
- Dedicated real case ID/profile separates these records from SYN-MAPLE. Existing history code can read the retained pending summary by actual H-MEM creation time. POST /api/research/history is fixed to the real case; it does not accept arbitrary case scope.
- The bridge labels new real-public-observation snapshots correctly instead of calling them synthetic. Confidence describes capture, never trust.

## User flow

In chat enter `refresh Lucy`, then `Lucy history`. The refresh shows memory status and saved ID; history reads the saved review. The latter is not a new source check. Default results omit internal role trace. `/api/debug` now contains separate real_latest_run for explicit local developer inspection. It is not production operator authentication.

The reader's25second worker plus two bounded15second memory operations can take55seconds in the worst case. The shared browser client and research live-read timeout are now65seconds. Timeouts do not cancel server work and never trigger automatic retries. Repeat-click60second cache includes the review, so it does not save a duplicate snapshot. A later uncached review can add a new observation even with unchanged pages.

## Actual evidence this increment

- Browser refresh read_complete, official H-MEM saved mem-1 in REAL-LUCY-GHS; chat history returned recorded_review with real_public_observations. No payment, SQL or model calls.
- Integration tests use the real official H-MEM reference on controlled observation inputs: restart recall, prior-gap context, distinct case scope, preserved records, changed-source detection and unchanged-manual-input branch. Such inputs do not assert a real website changed between test phases.
- Partial read, failed memory and conditional resolver paths have deterministic tests. Missing configuration reports not_configured/history_unavailable, not a memory success.
- No guarantee of current clinical/funding/risk completeness. No claim that Nightshift is connected. The earlier saved manual CRA/form observations remain separate from live article reading.
