HOW IT WORKS

One evidence system.
Different questions.

Donors explore what supports an appeal. Rescue organizations learn what public information to add. Both views use the same observations and verification boundaries.

What runs today

Find organizations

Optional NVIDIA Nemotron interprets an ordinary request. Code validates its intent, queries the historical government directory through AWS-hosted Zetaris and checks permitted website pages. Candidates are not automatically trustworthy recommendations.

Inspect a public appeal

A supplied HTTPS link goes through network, robots and text checks. The system shows source observations, gaps and unknown funding. It saves the investigation using official Meterless H-MEM.

Operations depend on the question

Interpret and select

The coordinator asks for missing location, chooses a bounded lookup or website read, or recalls saved history. Direct URLs and explicit refreshes can bypass the model.

Read and check

Public-source collection feeds the shared observations and gap checklist. A blocked source stops with a reason. Follow-ups can reuse the current read; an explicit refresh starts another read.

Keep uncertainty visible

Medical words are not clinical proof. Historical registration is not current risk clearance. Without corresponding verified costs and funding received, the remaining amount stays unknown.

Memory and follow-up

H-MEM stores scoped observations. History recalls the selected directory investigation or website. A different source does not inherit Lucy's findings.

Tool responsibilities

NVIDIA Nemotron

Optional hosted intent classification, live-verified. Code validates output and writes replies. No independent evidence authentication by the model.

Zetaris on AWS

Real read-only JDBC queries over the configured CRA 2024 REST tables. Website reads use the application's separate public reader. AWS credentials are not needed by the app.

Meterless H-MEM

Official reference engine on Node; real local save and recall. No dedicated GPU needed. Nightshift is a separate, unconnected provider route.

Agent roles and actual limits

Orchestrator, collector, evaluator and resolver are code roles in one process. Not all run on every request. The curated Lucy review has conditional chronology resolution; the labelled fictional Maple example has a capped repair loop.

The general website workflow currently performs basic source and gap checks. Deeper credibility evaluation and automatic dispute resolution remain future work. A role in a diagram is not evidence that it ran.
